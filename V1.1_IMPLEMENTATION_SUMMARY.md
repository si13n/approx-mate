# Approxmate v1.1 — Advanced Tax Settings — Implementation Summary

## Overview

Approxmate v1.1 adds configurable tax profiles while maintaining the simple, one-number-in/many-results-out UX of the main calculator.

Users can now customize B2B and UoP tax assumptions without leaving the interface. All settings persist locally and recalculate instantly.

### Part 3: Calculation Engine

**New Module (`src/lib/taxCalculations.ts`)**

B2B Calculations:
- `calculateB2BFromGross()` — Gross → Net using selected profile
- `calculateB2BFromNet()` — Net → Gross via binary search
- Auto health tier selection based on annual revenue
- Proper deduction handling (social + 50% health)
- Supports all 3 ZUS profiles + sickness insurance

UoP Calculations:
- `calculateUoPFromGross()` — **Annual-first model**
- `calculateUoPFromNet()` — Reverse via binary search
- Annual ZUS cap (282,600 PLN) correctly applied
- PIT brackets (12%/32%) at 120,000 PLN threshold
- Tax reduction (3,600 PLN/year) applied
- KUP deduction (250/300 PLN)
- PPK contributions (2% employee) if enabled

**Key Improvements**
- All calculations use `TaxProfile` configuration
- Removed hardcoded tax constants from App.tsx
- Annual-first for UoP (required for correct tax calculation)
- Deterministic binary search for reverse calculations
- Safe handling of edge cases (non-negative net)

## Technical Highlights

### Annual-First Calculation for UoP
UoP tax law requires annual calculations:
```
monthly gross × 12
→ annual gross
→ apply annual ZUS cap
→ apply PIT brackets
→ apply tax reduction
→ ÷ 12
→ display average monthly net
```

Not: `calculate one month × 12` (this would give wrong results above threshold)

### Health Contribution Tiers (B2B)
Automatically selected based on annual revenue:
| Annual Revenue | Monthly Health |
|---|---|
| ≤ 60,000 PLN | 498.35 PLN |
| ≤ 300,000 PLN | 830.58 PLN |
| > 300,000 PLN | 1,495.04 PLN |

### Binary Search for Reverse Calculations
For Net → Gross, use deterministic numerical solver:
```
target net
→ guess gross
→ calculate net
→ compare
→ adjust bounds
→ repeat 64 times
→ converge on answer
```
